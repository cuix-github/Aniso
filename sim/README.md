# The simulation workstream: PF-FLIP in Bifrost

This folder implements the core of *Adaptive Phase-Field-FLIP for Very Large Scale Two-Phase Fluid Simulation* (Braun, Bender, Thuerey, SIGGRAPH 2025) inside Maya's Bifrost, using only the public Bifrost SDK and shipped nodes, and couples the result to this repository's Gaussian-splat pipeline: simulate a two-phase air-and-water shot in Bifrost, render the particles as Gaussians with Aniso inside a captured splat scene. The authors released only their grid data structure (MSBG, Apache-2.0), not the solver, so this is an independent implementation from the paper's equations.

## Why this paper, in three sentences

PF-FLIP fills air with FLIP particles too, so wind, splashes, spray, and air entrainment come from physics instead of "white-water" heuristics. Its phase field costs nothing: it is the splatted particle mass, normalized, so there is no level set and no surface reconstruction anywhere. The only genuinely new machinery over textbook FLIP is a variable-coefficient pressure solve, where each cell face is weighted by the mass that landed on it.

## Architecture decisions (settled)

- **Uniform-grid pressure solve, adaptive particles.** The paper's grid adaptivity (its Sections 4 and 6) exists to reach ocean scale; a room-scale shot does not need it, and the particle side (Section 5, including the per-size FLIP-blend correction of 5.3) is where the cost explosion actually is, because air fills the whole domain with particles. Escalation paths if footage ever demands more: higher uniform resolution, then static nested refinement, then a standalone build on the authors' Apache-2.0 MSBG. Consequence accepted: domain size is capped by the uniform solve; a snug box around the action.
- **One custom C++ node, everything else stock.** The two-phase pressure projection does not exist in the product (the shipped liquid and gas projections each assume a single density) and is our one SDK node. Verified stock wheels for the rest: `splat_points_into_volume` (arbitrary properties, linear or quadratic kernel, exposes accumulated weights, which *is* the phase field's raw material), `sample_property` for grid-to-particle, `transport_particles`, standard field math, and the public iteration machinery the shipped solvers themselves are built from.
- **Public surface only.** Shipped files, public SDK, public docs. The custom node reads and writes plain arrays attached as custom properties, deliberately independent of Bifrost's internal volume layout.
- **Reference first.** A small pure-Python 2D implementation of the core loop (`reference2d/`) is the executable spec; every Bifrost stage is validated against it and against the paper's own test cases.

## What is in this folder

- `bifrost/PFFlipSpike/`: the feasibility spike, a Bifrost SDK operator pack containing the variable-coefficient projection with a built-in 1D two-phase hydrostatic test. Build with `PFFlipSpike\build.bat` (needs Visual Studio 2022 and Bifrost 3.1 installed with Maya 2027); run with `run_hydro_test.bat`.
- `bifrost/hydro_test.json`: the bifcmd wrapper compound for that test.
- `bifrost/phase_field_probe.json`: the milestone-4 graph, stock nodes only: particles in from .npy, phase splatted into a volume with `splat_points_into_volume`, phi sampled at probe positions and written back as .npy. Its `view_volume` output carries the volume with fog density set to phi, so Maya's viewport shows the phase field directly. `run_phase_field_probe.bat` runs it headlessly; `compare_phase_field.py` drives the whole comparison against the 2D reference and writes the figure; `pfflip_graphs_config.json` exposes the compound to Maya (point `BIFROST_LIB_CONFIG_FILES` at it).
- `bifrost/phase_field_play.json`: the same phase-field graph made playable in Maya. `export_play_sequence.py` dumps the reference 2D dam break as a numbered .npy sequence, `build_maya_play_scene.py` wires a scene where Maya's timeline drives the graph's frame port, and `play_in_maya.bat` does all of it in one click: press play in the viewport and the fog you see is the phase field of the validated two-phase simulation, frame by frame.
- `bifrost/PFFlipSolve.{h,cpp}` (inside the pack's src): the milestone-5 step node. `solve_step_test.json` + `validate_step.py` run the lockstep comparison; `sim_2d.json` (regenerate with `generate_sim_graph.py`) is the full simulation loop, driven by `validate_loop.py` through `run_sim_2d.bat`.
- `reference2d/`: the 2D reference implementation and its validation scenes.

Spike results (2026-09-30): the projection returns a 1000:1 density-contrast column to rest at the 1e-6 level and reproduces the analytic hydrostatic pressure jump; unpreconditioned conjugate gradient needs 211 iterations at 64 cells and 1843 at 256, which is the measured argument for adding a preconditioner in 3D.

## Milestones, each with its "done when"

1. **Spike landed.** This folder builds and the hydrostatic test passes on a clean checkout. Done when `run_hydro_test.bat` reports max velocity after projection below 1e-4.
2. **2D reference validates the core loop.** Hydrostatic rest, a two-phase dam break, and a Rayleigh-Taylor instability, the last being a two-phase-only phenomenon no single-phase solver can produce. Done when RT fingers develop from a seeded perturbation and the dam break front advances plausibly, with images in the repository.
3. **Validation gate: the paper's claims tested comparatively.** Done 2026-09-30, passed: see `reference2d/VALIDATION.md` (single-phase FLIP baseline vs two-phase on a sealed trapped-air pocket; interface transport vs a grid scalar; the viscosity law calibrated; mixing measured). One carried instruction: recalibrate the blend-to-viscosity constant per implementation.
4. **Bifrost graph produces the phase field with stock nodes.** Done 2026-09-30: `phase_field_probe.json` reads the same jittered two-block slab the 2D reference seeds (identical particles via .npy), splats phase with the stock node, and the fields agree, mean |difference| 0.002, maximum 0.08 confined to the one-voxel interface band, interface midpoint within 0.03 voxels. Figure: `reference2d/results/validation/phase_field_bifrost.png`. Authoring facts that cost debugging time: a new point property needs `set_geo_property` (the `_data` variant only overwrites existing ones); `splat_points_into_volume` writes only into existing tiles, so build the volume from the points first with `points_to_volume`, and it needs fog density on or the volume has no voxels at all; give the splat one property name per node, a two-name filter string misbehaved.
5. **The custom node does the projection inside the graph loop.** Done 2026-10-05, validated in three layers. Lockstep: `PFFlip::Solve::step_2d` (the projection grown from the spike, plus the per-phase FLIP transfer and RK2 advection, mirroring the reference line by line) run on identical inputs matches python with the same CG iteration count and face velocities to 1e-6 (`validate_step.py`). Full loop: `sim_2d.json` runs the whole simulation inside one headless graph, an iterate whose state is the particle arrays, with the staggered channels assembled by stock splats via the shifted-points MAC trick; the dam-break front stays within 1.9 cells of the reference over the full run and post-projection divergence stays at solver tolerance (`validate_loop.py`). Physics anchors, no reference in the loop: hydrostatic column stays at rest, the sealed air cushion holds its 10.6-cell gap exactly as the gate measured, and 19:1 Rayleigh-Taylor grows textbook mushrooms. Sheets and curves in `reference2d/results/validation/bifrost_*.png`. Known honesty note: fixed substepping is at its limit. The dam break peaks at CFL 0.54; the splash demo (`demo_splash.py`, the violent three-way plunge sheet in `bifrost_splash_demo.png`) measures air-jet speeds up to 505 cells per second as the trapped film squirts out at impact, CFL 5 at that instant, with 137 of 560 substeps above 1. The rows still match the reference, which shares the same treatment at the same dt, but the lesson is PF-FLIP-specific and now measured: the fastest thing in a violent two-phase scene is the air, a phase free-surface solvers don't even carry, so milestone 6 requires CFL-adaptive substepping rather than treating it as polish.
6. **3D at small scale**, the complete uniform-grid picture: adaptive particles (coarsen far-field air, per-size blend correction), a multigrid-preconditioned solve (measured need: 200-500 Jacobi-PCG iterations in 2D), CFL-adaptive substepping (measured need: 505-cells-per-second air jets in the splash demo), and escaped-particle droplets and bubbles, pulled forward because the showcase scene demands them. Done when a 3D dam break in a box runs at around 128³ overnight or better and conserves volume reasonably, and a 3D plunge showcase shows crown splash, rising bubbles, and foam. Phase-1 progress 2026-10-06: `step_3d` landed with a geometric multigrid V-cycle inside flexible PCG. Validated three ways: at nz=1 it reproduces the 2D method in exact lockstep (533 iterations, both implementations); multigrid solves the same dam-break system in 9 iterations instead of 533 with the same solution to 1e-6; and a real 32x32x8 two-phase column returns to rest at 1e-7 with the analytic pressure jump within 4 percent. Remaining in this milestone: the 3D loop graph, CFL-adaptive substepping, adaptive particles, escaped-particle droplets, and the showcase.
6.5. **The adaptive-solve spike pair**, deliberately after 6 because its multigrid machinery is most of the work already done. Two separate claims, two gates: (a) the solver math in 2D, junction stencils, conservative transfer, convergence on an irregular hierarchy, validated as a numpy adaptive reference against the uniform reference on the gate scenes, then the node in lockstep; (b) the Bifrost foundation, a small probe that stores the adaptive grid in a native multi-depth volume and walks it through the preview-tier traversal API behind a one-file adapter. Honest expectation: little speedup at snug-box scale; the value is proof that the declared limitation is removable, and our own measured evidence for what the source reading said. 3D extension only if a shot demands it. **Spike 1, the profiling that gates the pair, done 2026-10-09** (`PFFLIP_PROFILE=1` prints per-phase node times; two finale-scale runs of 4 and 12 substeps resumed from the mid-bore overnight state, walls differenced so startup cancels): at 256x64x128 with 6.8M particles a production substep costs 96.4 s of wall, of which the entire custom node is 5.6 s and the multigrid-PCG pressure solve 0.9 s at 23 iterations — 0.9 percent of the substep, 16 percent of the node. Amdahl therefore caps a *perfect* adaptive pressure solve at about one percent of wall-clock. The bill lives in the graph layer (around 91 s per substep: the stock splat families over the particle arrays, plus the per-substep NumPy dumps), and even inside the node the particle pass at 4.5 s outweighs the solve five to one. Verdict: gate (a) remains available as solver craft, but neither gate buys milestone 7 anything measurable; if the hero scene needs speed, the measured target is the splat layer and the dump policy, not the solve.
6.75. **The fused transfer layer**, 2026-10-09, one day after the spike-1 profile (PR #37) put a price on the stock-splat convenience and Xue's green light flipped the stock-first posture for the one data path that dominated the bill. P2G moved from thirty stock `splat_points_into_volume` plus thirty `sample_volume` invocations per substep into one custom node, `PFFlip::Solve::p2g_3d`, which scatters every channel - mass, per-axis momentum, phase, the ST temporal weight - onto all three face grids and both size tiers in a single pass, straight into the flat arrays the step node consumes. The kernel is now the reference's Eq. 6 on the reference's face frames, so the pipeline moved *closer* to the paper, not further: the dam-break gate's historical 1.9-cell front gap against the reference - stock-kernel mismatch all along - halved to 1.0 cell and the centroid drift fell from 1.24 to 0.35 cells, with hydro-column grid divergence at 2.6e-7 (unit gate `validate_p2g.py`: reference operator at float rounding, independent 3D numpy at 2.4e-4, axis permutation bit-exact; system gate `validate_p2g_loop.py`). Receipts, resumed from the same mid-bore finale state as the spike with the stock baseline re-reproduced within 3 percent the same day: 96.4 s per substep to 10.22 s, **9.4x** at 256x64x128 with 6.8M particles (`bench_p2g_finale.py`), and 8.8x on the 20-second production bore-with-pillars demo whose side-by-side video with live compute clocks lives in `bifrost/results/p2g/` (`demo_p2g_speed.py`). `step_3d` untouched, channel semantics drop-in, every prior gate standing; the eps-inversion trick now reconstructs sums the fused node computed exactly, earmarked for retirement at the next cleanup. The scatter is serial and deterministic; threading it is a measured decision for later, not a reflex. **The exact pie, measured 2026-10-10** (`dump_gate` + P2GPROF landed with it; the full receipts are in the PR #40 description): a fused finale substep is 10.3 s = particle pass 4.6 + scatter 3.0 + pressure solve 2.3 + assemble/correct 0.2 + graph residual 0.3, and the per-substep dumps cost no measurable time — the `dump_every` port's value is disk, not clock. The solve is 2.3 s here, not spike 1's 0.9 s, for an understood reason: the reference's r = 1 kernel draws a sharper interface than the radius-1.5 stock splat, and the harsher beta contrast takes 33-55 MG-PCG iterations where stock needed 13-15 — fidelity bought at solver expense. Net position: the solve already carries 22 percent of the substep, the neighborhood the ST-FLIP authors' own Table 1 reports (26 percent, on 32 threaded cores with their adaptive multigrid on), so the pipeline already has the paper's cost shape. Agreed order from here: deterministic threading of the scatter and the particle pass (the two big slices; per-core our stage costs are within about 2x of the authors', so the missing factor is literally their 32 threads), then milestone 6.5a with its production case in hand. A further gated lever: the authors solve pressure to 1e-4 where we run 1e-6.
**Threading follow-through, 2026-10-10.** Destination-owned slabs now parallelize the fused P2G and the two particle-count scatters while retaining original particle addition order at every face. Independent particle work is threaded; the original RNG stream and merge/split order stay intact. Fresh same-day finale measurements are 8.26-8.44 s per substep before versus 4.44-4.62 s after at 32 workers, about 1.8x overall. The new measured pressure share is roughly 54 percent, so this configuration is the baseline for milestone 6.5a. Identity checks at 1/8/32 workers and a larger parallel flat case preserve every saved array exactly. The 20.04-second 3D bore also matches all 1,146 saved arrays, with zero represented-volume drift and zero actual-state solid penetrations. Nine existing regression scripts pass; the legacy stock-graph ST bubble-count gate fails identically on unchanged main and on the threaded build, with all 502 saved outputs identical. The bore audit separately catches display positions entering pillars in both builds. Both gaps remain open, not silently reclassified as passing. The experiment, phase breakdown, receipts, labeled comparison video and validation details are in [the threading record](bifrost/results/threading/README.md).

7. **The shot.** A captured real scene, box colliders aligned by hand, one violent release, particles exported per frame and rendered as Gaussians by Aniso inside the splat scene, whitewater coloured from the phase field. Scene choice is still open.

## Open questions

- Why does the existing stock-graph ST plunge produce 56 peak bubbles against the Python reference's 259, below `validate_st_loop.py`'s accepted band? The 2026-10-10 threading audit reproduced this failure on untouched main and found all 502 outputs bit-identical to the threaded build. The independent node and 3D smoke pass; see [the preserved evidence](bifrost/results/threading/README.md). Threading is complete as an equivalence-preserving change, while this older system-level discrepancy needs its own investigation.
- The 20-second 3D bore has zero actual-state obstacle penetrations but 1,225 display-position penetration occurrences across 125 frames, identically on baseline main and the threaded build. The final obstacle sweep precedes ST time resynchronization, which can put `out_pos_synced` back inside a pillar. Reconcile the earlier claim that synced positions were also clamped and define the intended collision-safe display output; preserve the solver-state trajectory while doing so. The diagnostic graph and failing audit are in [the threading record](bifrost/results/threading/README.md).
- Hero scene: to be chosen (current candidates: flash flood down a captured staircase; dam break through a doorway; violently filling a dry fountain).
- Preconditioner for the 3D solve: incomplete Cholesky versus a simple multigrid V-cycle. Milestone-5 data point: Jacobi-PCG needs roughly 200 iterations on a 64x64 hydrostatic column and about 500 mid dam break at 160x80, 1000:1; extrapolated to 128-cubed this argues for multigrid.
- SDK stability posture (settled 2026-10-04): the node exchanges flat arrays as custom properties and lets stock nodes touch volumes at the edges, which keeps us on the SDK's compact, property-centric core, the small include surface of object model plus geometry property access visible in any SDK install. Deeper native volume traversal exists for extension authors but without that core's stability expectations, so if profiling ever demands it, it goes behind a one-file adapter rather than into the solver.
- Grid adaptivity, position updated 2026-10-05: no longer a flat non-goal but a staged spike (milestone 6.5), after the uniform 3D build stands. Hierarchical depth is first-class in the volume container and cooperative at the conversion edges, but the depth-aware solving itself, halo exchange across levels, conservative transfer, mixed-resolution convergence, is ours to build and as yet untested by us, so it gets the same spike-then-gate discipline as everything else. The production path remains uniform solve plus adaptive particles in a snug box. Position updated again 2026-10-09 by milestone 6.5's spike 1: the profiled pressure share at finale scale is 0.9 percent of wall, so the adaptive solve is officially craft, not production path. Position updated a third time 2026-10-10, after the fused transfer layer (milestone 6.75) shrank the denominator and its sharper kernel raised the solve's own cost: the solve now carries 22 percent of a fused substep — the same share the authors' own per-stage table reports — so milestone 6.5a is back to being a production proposition, sequenced after deterministic threading. The lesson worth keeping from the 0.9-to-22 journey: a share is set by the whole pie, so never quote one from measurements taken in different pipeline configurations.
- ~~Whether the stock splat's kernel is smooth enough for a quiet phase field~~ — answered at milestone 4: the stock linear kernel's field matches the reference, and swapping the paper's Eq. 6 kernel for a tent kernel in the reference moves the interface midpoint by under 0.01 voxels, so kernel choice barely matters for the field; the custom node does not need the paper's exact kernel.
